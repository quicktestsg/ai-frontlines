The First Thousand Tokens Are Rent

Every call an agent makes re-pays the same fixed opening balance — system prompt, tool schemas, style rules — billed again at every iteration of the loop. Prefix caching can turn that rent into a one-time payment, but the discount is earned, not given. Token order is an infrastructure decision.

Start with the arithmetic nobody does. A production agent carries a preamble: system instructions, a dozen tool definitions with full schemas, formatting rules, safety constraints. Call it four thousand tokens, and call that charitable. A single task is not a single call — it is a loop. Thirty steps is ordinary; research sessions with subagents run into the hundreds. At thirty steps, that preamble is processed thirty times, and nothing about it ever changed. The model re-reads the same instruction manual on every turn, as if each call were the first. The bill scales with the loop; the information does not scale at all. That is the definition of rent.

Serving stacks have an answer for this: the prefix cache. KV states for the head of a request are computed once and reused for any later request whose head is byte-identical. The cached region is processed at a steep discount — a tenth of input price on the major providers, sometimes free, occasionally still full rate. The details vary; the shape does not. Identical prefix, cheaper tokens. Divergent prefix, full price. What is quietly revolutionary is where control lives: the cache matches on bytes, and the harness decides the bytes.

Left: the uncached harness — the fixed preamble is re-processed at full input price on every step. Right: the cache-aware harness — everything up to the cache frontier is byte-stable and billed at the cached rate; only the volatile tail pays full price. The blocks are the same blocks. Only their order changed.

Order the prompt like a ledger

The cache matches from the first token forward and stops at the first byte that differs. Not the first sentence — the first byte. A timestamp in the system prompt, a session ID, a greeting that interpolates the user's name, a tool list sorted by hash-map insertion order: any of these forks the prefix at token twelve and takes the discount to zero. The discipline is almost embarrassingly mundane: sort the prompt by rate of change. Immutable ledger entries first — identity, constitution, tool contracts. Semi-stable entries follow — retrieved documents, keyed so identical retrievals produce identical bytes. Volatile entries go last, at the tail, where mutation is cheap. Built this way, the cache frontier is a straight, legible line. Built any other way, it zigzags at the whim of whatever library assembled it.

This is bookkeeping, and it deserves the respect bookkeeping gets everywhere else in the stack. Accountants learned centuries ago that fixed costs go in the ledger and variable costs go in the day book. Prompt construction has the same shape. Teams that internalize it stop treating the preamble as prose and start treating it as an artifact with an owner, a version, and a stability contract. Tool schemas get deduplicated and frozen. Environment descriptions move from head to tail. Personalization is exiled to the last few hundred tokens, where its variance costs cents instead of the whole discount. None of this appears in a benchmark. All of it appears in the invoice.

The cache does not care what the tokens mean. It cares that they are the same. Meaning is the model's business; sameness is the harness's business. The engineers who internalize this stop writing prompts and start writing invariants.

The prompt as a ledger: blocks sorted by rate of change, immutable at the head, volatile at the tail. The cache frontier sits wherever byte-stability ends — as high as the harness can push it. One interpolated timestamp above the line relocates the frontier to the top and resets the discount to zero.

The loop is the amplifier

A chat application pays the preamble once per message — a rounding error. An agent loop pays it once per step — the dominant term. A thirty-step run with a stable prefix pays full price for the first step's preamble and roughly a tenth for the other twenty-nine. The same run with an unstable prefix pays full price thirty times. Nothing in the model changed. Nothing in the task changed. The entire difference lives in the harness, in the ordering of strings, in a place where no one thought an engineering decision existed. The cache is the mirror of amortized intelligence: the mechanism that lets the loop amortize its own fixed costs.

The history block is volatile and cacheable at the same time: step n's prompt is step n−1's plus appended messages, and appended bytes do not invalidate what precedes them. Every rewrite of history — a summarizer that compresses the transcript, a pruner that deletes stale tool outputs — buys context back at the price of the cache. Sometimes that trade is worth it, late in a long run when the tail dwarfs the preamble. But it should be a decision with a number attached, not an accident of a library that rewrites the transcript whenever it feels like it.

Over a thirty-step loop, the unstable prefix pays full input price on every step; the stable prefix pays once and rides the cached rate, with cost creeping up only as the appended history grows. A mid-run compaction trades cache for context — visible, priced, and scheduled, or invisible and paid anyway.

Discounts you cannot bank on

There is a temptation to treat the cached rate as the new list price and re-plan the product's economics around it. Resist it. The prefix cache is best-effort infrastructure, not a contract: entries are evicted on a clock measured in minutes, and on shared serving they are evicted by strangers. A burst of parallel subagent calls warms each other's prefixes; a quiet night lets them all go cold; a neighboring workload can age the cache out between two steps of the same run. The discount is real, repeatable, and worth engineering for. It is also weather. The budget should be written for the cold path, with warm savings treated as margin. Teams that bank the discount as baseline discover this the month a provider changes an eviction policy — and the discovery arrives as a bill.

None of this is glamorous, and that is precisely the point. The history of infrastructure is the history of unglamorous invariants — reference counting, connection pooling, cache line alignment — that separate systems that scale from systems that merely work. Prompt-stability is the newest member of that family. It will not move a benchmark, and it is invisible in every architecture diagram that shows boxes and arrows. It shows up in one place: at the end of the month, in the number that determines whether the loop can afford to run as long as the task actually needs. Loop engineering learned that the loop needs a budget, a working set, and an exit condition. Here is the fourth law, arriving late and holding a receipt: the loop also needs to stop paying rent on what it already owns. The first thousand tokens are an asset. Whether they behave like one is a choice made in the harness, one byte at a time, starting with the first.
