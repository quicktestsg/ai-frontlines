The Idempotency Tax

Agents retry. The infrastructure beneath them retries harder. Every agent lives in an at-least-once world, and idempotency is the tax that world charges.

Here is a story that has happened to every team that has shipped an agent with write access to anything. The agent is asked to file a report. It calls the submission tool. The network hiccups; the request times out on the client side but completes on the server side. The agent, being sensible, retries. The tool succeeds again. Somewhere downstream, a second report is now filed, identical to the first. Nobody notices for a week.

Distributed systems engineers solved this problem decades ago, and the solution has a name that sounds like homework: idempotency. An operation is idempotent if performing it twice has the same effect as performing it once. Turning a light switch to 'on' is idempotent. Pressing a doorbell is not. The entire discipline of designing reliable systems over unreliable networks reduces, in large part, to converting doorbells into light switches.

One logical intent fans out into multiple physical executions: a timeout that half-succeeded, a defensive retry, and a model that simply lost count. Each path is individually reasonable. Together they triple every side effect.

Agents make the old problem worse in a new way

Classic distributed systems had one source of duplication: the infrastructure. Agents add a second, stranger source: the decision to act is now generated, not programmed. A model whose context was compacted may conclude the report has not been filed yet — and file it. The retry is not a mechanism anymore. It is a belief.

This is why naive porting of the old solutions fails. An idempotency key attached to a request works only if the same key is attached to every replay. When the replay originates from a model's fresh belief, it generates a fresh key — and the deduplication layer, working exactly as designed, waves it through.

The old question was: what if the network replays this request? The new question is: what if the mind replays it? The first is an engineering problem with an engineering answer. The second requires the system to know what it has done even when the reasoner does not. Memory of action must live outside the actor.

Pay the tax at the edge, where the action meets the world

The fix is not to make the model remember. The fix is to make the boundary between the agent and the world idempotent — to put the memory of action in the tool layer, where it survives anything the model does or forgets.

Every call carries the same operation reference, derived from the plan rather than the model's belief state. A ledger at the tool boundary records completed operations and their results. The world sees one execution. The model sees a consistent history it can trust.

The ladder of repeatability

Not every action needs the full ledger treatment. Actions sit on a ladder of repeatability, and the engineering discipline is matching the rung to the stakes — from free retries on reads, to upserts, to keyed logs, to fenced creations, to the confirmation gates that guard the irreversible.

Every agent action sits somewhere on this ladder. Reads repeat freely. Upserts repeat harmlessly. Keyed logs detect repeats. Fenced creations refuse them. Irreversible actions demand a confirm gate whose approval itself carries the operation reference.

There is a deeper payoff beyond correctness. An agent bounded by idempotent tools becomes braver, and bravery is performance. When retries are free of consequences, the agent can treat flaky tools as flaky — catch the error, call again, move on. The tax buys more than safety. It buys a system that can be aggressive about retrying the things that should be retried.

None of this is glamorous. Nobody demos a deduplication ledger at a conference. But the industry is entering the phase where agents stop being chat interfaces and start being operators. In that world, 'is this action safe to repeat' is the load-bearing question, asked of every tool, on every rung, before the first call is ever made. The at-least-once world does not negotiate. It only presents the bill — and it always charges less at design time than it does in production.
