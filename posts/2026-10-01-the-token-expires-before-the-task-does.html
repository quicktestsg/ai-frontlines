The Token Expires Before the Task Does

Agent tasks now routinely outlive the credentials they were launched with. When the credential dies mid-loop, the failure arrives wearing the costume of something else — a tool error, a rate limit, or most dangerously, an empty result set the agent happily believes.

Every authentication system in production was designed around a human attention span. Session tokens live for an hour because a person logs in, does something, and closes the tab. Then agents arrived and broke the assumption invisibly: nobody is standing there, and the tab intends to stay open for a week.

The core mismatch: a task is a single continuous intention; its authority to act arrives in fragments, each with an expiry. Refresh tokens patch some gaps and introduce others — consent lapses, rotation races, refresh windows shorter than the sleep between two steps of a slow loop.

The 401 that dresses up as everything else

The first failure shape is honest: the call fails. But the harness flattens 'server rejected your credentials' and 'server hiccuped' into the same error string, so the model retries — same credentials, same rejection. Then comes the fallback ladder: a different tool, a cached copy, a public endpoint. Each fallback is a small degradation dressed as resilience.

The empty result is worse than the error

Some authorization failures do not return errors — they return nothing. An expired scope returns an empty event list. A lapsed permission returns zero hits. The model treats the empty result as confident data: the calendar is clear, the feature does not exist, no customers churned. Nobody failed. An authentication artifact impersonated a fact about the world.

One expiry event, two downstream disguises. The error disguise leaves evidence. The empty-set disguise is worse precisely because it succeeds: every call returns 200, and the corruption surfaces only when someone notices the conclusion was wrong — at which point the transcript shows a spotless run.

A credential that expires mid-task does not stop the agent. It stops the agent from being right — and lets it keep being confident. The most dangerous failure in a long-running loop is the one that produces no error at all.

The lease is the vocabulary that fits

Distributed systems named this correctly long ago: the lease — permission with a timer attached. A lease-aware harness knows the expiry of every credential, renews at seventy percent of lifetime rather than at rejection, and fences with generation numbers so a rotated-out secret cannot keep succeeding from a stale process.

A lease-aware loop: pre-flight compares credential lifetime against the task estimate; every call carries a fenceable generation number; renewal fires at seventy percent of lifetime; and renewal failure triggers a durable pause — never a quiet fallback to an unauthenticated source.

The design smell that predicts this failure class: the credential check happens at launch and never again. But the token is the one value in the environment guaranteed to change during the run — changing is its job. Authentication left the perimeter and entered the loop. It is a continuously consumed resource, and it deserves budgeting, monitoring, scheduling, and fencing like any other.
