What the Agent Forgets on Purpose

Every long-running agent loop hits the same wall: the context window fills. What happens next is treated as plumbing. But the choice of what leaves the window is one of the most consequential design decisions in the entire system.

There is a moment in every extended agent run that nobody celebrates and everybody depends on. The loop is a hundred steps deep. The window is nearly full. Something has to go. In most harnesses, the something is chosen by code written in an afternoon: keep the system prompt, keep the last k turns, summarize everything older, carry on. The run survives — and nobody asks which kinds of truth were destroyed by the compression. Compression is never neutral.

The occupancy signature of a long agent run: steady growth, a compaction cliff, regrowth, another cliff. The difference from a GC heap is what lives inside the allocated bytes. In a GC heap, a surviving object is bit-for-bit identical. In a context window, what survives is a lossy retelling — produced by a model, wearing the tone of authority.

The window is a cache, not a record

The first conceptual error is treating the context window as the agent's memory. It is not memory; it is the current working set — the set of items the model can attend to right now, at full fidelity, with ordering and provenance intact. Everything else is archive: reachable only through retrieval, re-entering the window as a quote rather than a lived event. A cache miss costs latency. An archive miss costs knowledge the agent no longer knows it ever had.

Operating systems solved an isomorphic problem decades ago and left behind vocabulary worth stealing. The working set of a process is the set of pages it needs to avoid thrashing. The agent equivalent is crisp: the minimal set of items the model must attend to in order to choose the next action well — the goal, the artifact state, the guardrail constraints, the open questions. That set is small. Most of what fills the window is allocation churn, not working set.

A context window is not memory. It is attention, and attention is a budget. Every eviction policy is a theory of value — a claim about which facts deserve the model's finite gaze. The harness encodes that theory whether or not anyone wrote it down.

Summaries lose the part that made the record true

The standard compaction move — summarize the old turns — fails in a specific, predictable way. A raw observation carries metadata that the summary flattens: which tool produced it, when, with what confidence, in what order. The summary keeps the claim and drops the certificate. Later, when the summary says the migration succeeded and the database disagrees, the conflict is unresolvable except by re-deriving everything from the world.

The same overflow, handled two ways. Summarizing in place converts evidence into assertion. Externalizing the verbatim record to an archive — keeping only a compact, pointed summary in the window — preserves the ability to check the original whenever the world disagrees with the story.

This reframes what a good harness actually does at compaction time. It does not compress the transcript; it moves it. The old turns go to durable storage with metadata intact, and what re-enters the window is not a retelling but a directory: a short list of what happened, each line carrying a pointer back to the full record. Retrieval should return the original, not another summary of the original.

Eviction policy is product policy

There is no neutral way to decide what leaves the window. Keeping the last k turns privileges recency over relevance. Summarizing by topic privileges abstraction over sequence. Dropping tool outputs but keeping calls assumes results are re-derivable — false the moment a result came from a side-effecting tool. The bug reports read like personality changes: the agent stopped checking constraints, forgot the morning's instruction, confidently repeated a finished step. These are eviction policies whose consequences finally became visible.

A working-set architecture for agent context. The hot tier is small and task-shaped. The warm tier is a directory of pointers into the cold tier, which holds verbatim records. Demotion moves data down without loss; promotion brings the original back on demand. The loop between the tiers is the agent's memory.

Teams spend weeks tuning prompts and days choosing models, then let a fifty-line compaction routine decide, invisibly, what their agent is allowed to know. That routine steers behavior more than half the prompt combined — it is the prompt, rewritten every few hundred turns by code no one reviews. Designing the forget curve is part of the agent working.
