The Model Cannot Grade Itself

An agent ships an answer — fluent, structured, confident. Then the question arrives that every team dreads: is it correct? The instinct is to ask the model. The same model, or a bigger one, or the same model again with a stricter prompt. This is the most common and most expensive mistake in agent engineering, and almost every team makes it, because it feels like diligence.

There is a moment that repeats in every team building agents. The agent produces output that looks right. It is grammatical, well-organized, even hedged in the right places. Nobody on the team can tell, by reading it, whether it is correct — because the task is exactly the kind where correctness requires work the team did not do, a lookup the team did not perform, a computation the team did not run. So someone says the sentence that dooms the project: let's have the model check it. A second call is made. The model is given the first answer and asked whether it is correct. The model says yes. The team relaxes. The answer was wrong.

The generate node and the grade node draw from the same well: the same trained weights, the same learned priors, the same blind spots. When the generator makes an error rooted in a gap its training never filled, the grader has the same gap. The loop confirms itself. Two calls, twice the cost, and an error rate that barely moved.

Confidence is not correctness

Language models produce two things at once, and most teams conflate them. The first is the answer. The second is the fluency with which it is delivered. Fluency is the model's strongest, most reliable capability — it can make any claim sound measured, any fabrication sound sourced, any omission sound like a deliberate hedge. Fluency is also the signal the team reads when it eyeballs the output, and it is the signal the model reads when it grades its own output. The problem is that fluency is uncorrelated with truth. A model can be equally fluent while being completely right and completely wrong.

Asking a model whether its own answer is correct is like asking a counterfeiter to inspect the bill they just printed. They will always approve it. They made it. The inspection has to come from someone who did not print the bill — someone whose judgment does not share the counterfeiter's blind spots. Verification is, by definition, an outside job.

The verifier asymmetry

Generating a correct answer and verifying a given answer are not the same problem, and they do not require the same tools. This is the deepest misunderstanding in the field. Teams assume that if a model is smart enough to produce an answer, it is smart enough to check one. But generation and verification operate on opposite ends of the information gap.

Generation searches the whole space for one correct point — slow, probabilistic, expensive. Verification asks a single yes-or-no about one given point — fast, often deterministic, frequently cheaper by orders of magnitude. The two problems look related because they touch the same content. They are not the same problem, and the cheapest correct verifier for a task is very often not a language model.

Consider what it actually takes to verify different kinds of agent output. If the agent computed a number, the verification is to recompute it deterministically — not to ask a model whether the number looks right. If the agent cited a source, the verification is to fetch the source and check that it says what the agent claims — not to ask a model whether the citation seems plausible. If the agent wrote code, the verification is to run the code and check that the tests pass — not to ask a model whether the code looks correct. If the agent made a claim about a document, the verification is to search the document for the claim. In every case, the reliable verifier is an operation against ground truth: a calculation, a retrieval, an execution, a lookup. The model is involved in none of them.

The ladder of independent signals

This is where the architecture gets interesting. Verification is not a single node tacked onto the end of the loop. It is a ladder of signals, each independent of the generator, each catching a different class of failure, each cheaper than the one above it. The strongest teams build this ladder deliberately and run it in order.

The ladder runs cheapest-first. Deterministic checks and ground-truth lookups catch structural and factual errors for fractions of a cent. Execution catches logical errors for the cost of a sandbox. Only after these gates does an independent model verifier run — and even then, it is a different model with a fresh context and its own tools, not the generator rereading its own words. Human review is the last rung, reserved for the thin slice that survived everything below.

The reason this ordering matters is not just cost, though the cost savings are dramatic. It is that the cheap checks are also the most reliable. A deterministic recomputation is never wrong about whether two numbers match. A source lookup is never wrong about whether a document contains a sentence. These checks do not hallucinate, do not get confused by fluency, do not approve a confident wrong answer because it sounds right. They are immune to exactly the failure mode that makes model self-grading useless. Every failure they catch is a failure the model grader would have let through.

When a model grader is the right tool, and how to use it wrong

None of this means model-based verification is never useful. It means it is the most overused and most poorly applied technique in the field, and that it earns its place only at a specific rung of the ladder, under specific conditions. A model verifier helps when the task has no computable ground truth — open-ended writing, subjective quality, creative alignment with a brief. In those cases, a model that is independent of the generator, given fresh context and the ability to re-derive the answer itself, can surface disagreements that a human reviewer would also surface. But this only works if the verifier is actually independent: a different model, or at minimum the same model with a fresh context window that contains none of the generator's reasoning.

The teams that get this wrong do it in three predictable ways. They grade with the generator instead of an independent model, sharing the same blind spots. They grade with context contaminated by the generator's reasoning, so the verifier is anchored to the answer it is supposed to question. And they treat the grader's verdict as ground truth, when it is itself a probabilistic guess that needs its own calibration. Each of these turns a potentially useful signal into a false sense of security — the most dangerous output an agent system can produce, because it suppresses the human review that would have caught the real error.

The most expensive thing in an agent system is not the wrong answer. It is the wrong answer that passed a check, because that answer stops being questioned. Verification that cannot fail is not verification. It is theater, and theater is worse than nothing, because nothing at least leaves the team uncertain enough to look.

Build the ladder, not the mirror

The practical takeaway is uncomfortable for teams that have already built self-grading into their pipeline, because it means the check they trust is mostly decorative. The fix is not to remove model-based grading entirely. It is to demote it to its correct place — one rung among several, never the only rung, never the first rung, and never the generator grading itself. The bulk of the verification budget should go to the deterministic and ground-truth checks that sit below it on the ladder, because those are the checks that actually fail when something is wrong, and that fail cheaply, reliably, and without being charmed by fluency.

The model is a brilliant generator. It is a mediocre, easily-charmed verifier of its own brilliance. Treating those as the same capability is the original sin of agent reliability. The answer the agent ships is only as trustworthy as the most independent signal that checked it — and the most independent signal is never the voice that produced it. Build the ladder. Run it cheapest-first. Let ground truth do the grading wherever ground truth exists. And reserve the model's judgment for the narrow band where nothing else can reach, used as one skeptical voice rather than the final word. The agent that grades itself is an agent that has decided, in advance, never to find its own mistakes. That decision is the mistake.
