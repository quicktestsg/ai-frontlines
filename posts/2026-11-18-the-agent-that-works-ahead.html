The Agent That Works Ahead

Watch a slow agent and the model is almost never the bottleneck — the gaps are. Between one turn and the next, the loop sits idle: waiting for a tool to return, waiting for a branch to be confirmed before anyone starts walking it.

There is a particular flavor of slowness that afflicts agent systems and mystifies the people who build them. The trace looks innocent. The model thinks for four seconds, the tool runs for two, the model thinks for four more. Nothing is pathological. Yet the end-to-end time for a forty-step task is six minutes, of which perhaps ninety seconds is the model actually producing anything. The rest is the loop being perfectly, deliberately, wastefully serial.

Computer architecture hit this wall decades ago, and the answer it found is worth stealing wholesale. A modern CPU does not wait to learn whether a branch goes left or right; it guesses, begins executing the guessed path immediately, and keeps a precise record of how to undo everything if the guess proves wrong.

Top: the obedient loop, where every step waits for explicit permission from the previous one and the pipeline idles between turns. Bottom: the speculative loop, where a predictor runs alongside the main loop, filling the gaps with probable work — prefetching tool inputs, warming the likely branch — and discarding it cleanly on a miss.

Three things worth predicting

Speculation is not one technique but a family, and the members differ by what they guess. The first and easiest is value speculation: predicting the content of a tool result before the tool returns. Most tool calls are highly predictable in shape — a file read returns the file, a database query returns rows matching a filter the agent itself just wrote.

The speculation stack, ordered by what gets guessed. Value speculation predicts tool results and prefetches inputs; plan speculation walks probable branches in a sandbox before the branch is confirmed; environment speculation keeps the surrounding world warm — indexes, tokens, builds. All three live strictly inside the reversible envelope.

The reversible envelope

Speculation in a CPU is safe because silicon has a property agent systems mostly lack: mis-speculation is free. The processor discards the wrong path with a flush and nothing in the world has changed. An agent does not have that luxury by default — its tool calls touch databases, send emails, spend money.

A wrong guess inside the reversible envelope costs compute. A wrong guess outside it costs trust. The envelope is not a limitation on speculation — it is the only reason speculation is allowed to exist.

The second discipline is metering. Speculation is a bet, and bets need bookkeeping. Every speculative path carries its provenance — what was guessed, on what evidence, what it cost — and the harness tracks a running hit rate. When the predictor is doing well, the budget for parallel guesses grows; when it degrades, on a novel task or an unfamiliar toolchain, the budget collapses back toward obedience automatically.

The bookkeeping that makes speculation trustworthy. The predicted path and the actual path are diffed; the meter tracks hit rate and the bounded cost of misses per task type. While guesses land, the speculation budget grows. When accuracy collapses, a kill switch throttles the agent back to obedient mode automatically.

There is an objection worth taking seriously: that this is a lot of machinery for latency, and latency is vanity. It is not. Latency determines the granularity of delegation. An agent that answers in seconds can be used in conversation, corrected mid-flight, woven into a human's flow. An agent that answers in minutes is a batch job, consulted reluctantly and audited after the fact.
