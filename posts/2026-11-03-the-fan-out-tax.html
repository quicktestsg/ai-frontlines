The Fan-Out Tax

Multi-agent systems are sold on a seductive image: one orchestrator spawning a dozen subagents, each burning through its own context, all working in parallel while the wall clock barely moves. The image is true right up to the moment the work comes back. Because every branch that fans out must fan in — and the fan-in happens through a single context window, one attention head at a time. Parallelism on the way out; serialization on the way back. The tax is levied at the border, and almost no architecture budgets for it.

Start with the ledger everyone quotes. A subagent gets a fresh context: it does not inherit the parent's cluttered transcript, so it thinks cleanly, and its scratch work does not pollute the main thread. Ten subagents mean ten isolated windows, ten parallel chains of thought, ten tool budgets. On paper this is a tenfold multiplication of thinking. The paper is not wrong about the fan-out. It is silent about the fan-in. When those ten branches finish, their results must return somewhere, and the only somewhere that can act on them is the orchestrator's context window — a fixed-size attention budget that now has to absorb ten reports, reconcile their contradictions, track their provenance, and decide what to do next. The work was parallel; the understanding is not.

The textbook diagram of multi-agent systems draws only the left half: one node becoming many. The right half is where systems live or die. Every spawned branch produces a result that must be read, believed or verified, reconciled against its siblings, and folded into a decision — inside one context window whose size did not grow just because the organization chart did. Spawning is O(1) in attention. Merging is O(n) in attention, O(n) in tokens, and — because contradictory results must be adjudicated — occasionally O(n²) in reasoning.

Three line items on the tax bill

The fan-out tax is not one cost but three, and they compound. The first is the transport cost: raw results are the wrong currency. A subagent that spent twenty tool calls arriving at a conclusion wants to return its journey; the parent can afford only the destination. Someone must compress, and compression is where nuance dies — the caveat that would have changed the decision is exactly the sentence that gets cut. The second is the attention cost: context is not storage, it is spotlight. Every result that enters the window competes for attention with everything already there. Insert five dense reports and the model's effective recall of the original task measurably degrades. The window did not overflow; the focus did. The third is the verification cost, the one nobody prices. A result from a branch is a claim. The orchestrator can trust it, or it can check it, and checking is itself work that lands in the same exhausted window. Most systems quietly choose trust, which is why multi-agent pipelines fail not loudly, at the branch, but softly, at the merge.

Three costs, one merge point. Transport strips the caveats that mattered; attention dilutes the goal the whole system was supposed to serve; verification gets skipped because there is no budget left to pay for it. The result is the characteristic multi-agent failure that shows up in the wild: every subagent's transcript looks impeccable, every intermediate result is defensible, and the final output is confidently, tracelessly wrong. The postmortem finds no bug — because the defect was never in a component. It was in the accounting.

A multi-agent system is not a team of thinkers. It is a team of workers and a single reader. The architecture does not scale thinking; it scales labor — and then hopes the one context window left standing can hold the whole world the labor uncovered.

When fan-out actually wins

None of this is an argument against multi-agent systems; it is an argument for knowing what they are good at. Fan-out wins when the task is embarrassingly parallel — when branches need almost nothing from each other and the merge is cheap. Searching forty files for the same pattern. Checking two hundred endpoints for the same bug class. Running the same verification over ten configurations. In each case the result is a uniform shape, contradictions are rare, verification is mechanical, and the merge is closer to a concatenation than a synthesis. Fan-out also wins on isolation grounds: when a branch might get poisoned — by a hostile document, a confusing codebase, an adversarial web page — a disposable context is a containment boundary, and burning it is cheaper than cleaning the main thread. The pattern to internalize: parallelize the doing, never the deciding. Subagents should gather evidence, not render verdicts. The moment branches return opinions that must be argued into a consensus, the merge has become the hardest reasoning problem in the system — and it is being solved by the most overloaded context window in the system, which is exactly backwards.

The same topology, two different systems. Left: branches return facts in a uniform schema, and the merge is mechanical — this is fan-out paying for itself. Right: branches return conclusions, the conclusions disagree, and the orchestrator must now run a debate, weigh evidence it never saw, and pick a winner — using attention that was already spent. The geometry is identical; the economics are opposite. What separates them is not the org chart but the shape of what crosses the border on the way back.

Designing around the tollbooth

If the merge is the bottleneck, the design moves are all ways to keep the border crossing cheap. First, dictate the shape of returns: a subagent should be contractually bound to a schema — findings, confidence, evidence pointer — so that merging is parsing, not reading. Second, merge outside the window: results land in a shared workspace — a file, a table, a structured store — and the parent queries summaries rather than ingesting reports; the context window reads the index, not the archive. Third, appoint a reducer: when many results must become one, let a dedicated context do the folding in stages — a tree of merges rather than one heroic gulp — so no single window ever holds the whole harvest. Fourth, keep verification out of band: checkers that read the workspace and grade the merge against the original spec, returning a pass or fail rather than an essay. None of this removes the tax. It converts it from a surprise, paid in attention at the worst possible moment, into a budgeted line item, paid in storage and extra passes at the edges where it is cheap.

The deepest of these moves is the second, because it reframes what a multi-agent system is. The naive picture is agents talking to agents — intelligence wired to intelligence, and the context window as the meeting room. The durable picture is agents writing to a world — a shared, structured, queryable state that outlives any window — and talking only through it. Organizations of humans discovered this a long time ago: the way to coordinate a thousand people is not a thousand-person meeting, it is a library, a ticket queue, a shared ledger, a status board. Context windows are meetings. Workspaces are institutions. The fan-out tax is what a system pays when it tries to run an institution through a meeting. Build the institution instead, and the meeting gets short: who is doing what, what changed since yesterday, what needs a decision. That is a meeting a single window can survive — and a system that runs overnight can afford.

So the accounting discipline for multi-agent architecture, in one paragraph: before adding a branch, price the return. Ask what crosses the border on the way back — facts or verdicts — and how much attention the merge will cost the window that has to hold the goal. Give every subagent a return schema and a shared workspace to write into, so the parent reads an index instead of an archive. Parallelize gathering, isolating, and verifying; never parallelize deciding. And when a design starts drawing org charts with more than a handful of agents, remember that every arrow pointing back at the orchestrator is a toll. The systems that scale are not the ones that spawn the most. They are the ones that designed the cheapest way home.
