Context Is a Cache — Treat It Like One

Everyone talks about the context window as if it were memory, and every long-horizon agent fails as if it were a database stuffed past capacity. The window is not memory. It is a cache.

Watch a long-running agent degrade and the pattern is always the same. Steps 1 through 40 are sharp. Around step 80, it starts re-reading files it already read. By step 150 it forgets a constraint stated at the top of the session. Nothing crashed. The transcript just kept growing, and quality quietly bent under its weight.

The same window, early and late in a run. Early, everything fits. Late, the window holds the residue of two hundred steps while the one constraint that mattered got evicted. The model did not get worse. The cache got dirty.

The working set, not the window

Operating systems taught this in the sixties: a process needs a working set — the small collection of pages it is actively touching. A coding agent at step 200 needs roughly five things: the current goal, the binding constraints, the file state, the last few tool results, and the plan's next move. Almost no harness computes this explicitly.

A bigger window does not give an agent a better memory. It gives its garbage a longer lease. Coherence at distance is an eviction policy, not a token count.

Eviction is a design decision, not a default

When context pressure rises, every harness does something — but most do it accidentally. Truncation is an eviction policy. Summarization is an eviction policy. Even 'let the model decide' is an eviction policy. The point is that these should be chosen deliberately, per category of content.

Four ways to deal with a full window, from accidental to designed. Truncation is blind. Summarization is lossy. Pin-and-demote classifies content. The state block regenerates the working set every turn, so coherence stops depending on luck.

Admission and prefetch

The other half of cache design happens before anything enters the window. Admission policy asks: should this content be in context at all? Tool outputs get a one-line stub in context and full bodies in external storage. Retrieval should fetch pointers, not payloads. Prefetch is the mirror skill: stage what the next step probably needs before the model asks.

The component almost no agent stack has: a memory manager between tools and model. Raw payloads spill to an external store; only stubs enter context. Prefetch stages what the next step needs. The model never sees the landfill — only the working set.

Windows will grow. The discipline will not expire.

The obvious objection is that windows are getting bigger and the problem will be outgrown. It will not. Longer horizons expand to fill whatever window exists. Caches did not disappear when memory got cheap; they multiplied. Measure the working set, not the window.
