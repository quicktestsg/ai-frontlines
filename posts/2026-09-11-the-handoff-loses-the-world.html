The Handoff Loses the World

Every multi-agent system is sold on a promise: divide the work, run the specialists in parallel, and the whole becomes smarter than its parts. What the diagram never shows is the seam.

Start with the observation that every advocate of multi-agent architectures eventually confronts. Two agents, each running the same model, will produce worse work together than one agent running alone — unless the handoff between them is engineered with real care. The subagent is not stupid. It is amnesiac by design. It never saw the world; it saw a summary of the world.

The sender holds a world: history, intent, dead ends, priors, taste. The seam compresses it into a task spec. The subagent wakes up as a competent stranger — technically capable, contextually blind.

Delegation is compression

The information theory here is unforgiving. A long-running agent's context is a high-dimensional state. A handoff is a projection of that state into a low-dimensional artifact. Projections lose information by definition — the only question is which information, and the sender is in the worst possible position to answer, because what matters is determined by the future work, which has not happened yet.

Every handoff is a bet that the sender correctly guessed which parts of its world the receiver will need. The bet is placed at the moment of least information and it cannot be retracted. Single-agent systems never place this bet. That is their inefficiency, and also their entire advantage.

The world state is tacit

There is a useful distinction between two kinds of knowledge inside a running agent. Explicit knowledge is what has been written down. Tacit knowledge is everything else — the shape of the problem, the disqualified approaches, the sense that the user cares more about latency than elegance. Agent teams are repeating the documentation mistake at machine speed.

Three places the world can live. In the handoff: fat, brittle, stale. On a blackboard: shared, structured, outliving any context. In the environment: no transfer at all — the subagent re-derives what it needs, because the repo is the world, not a description of it.

Contracts, blackboards, and re-derivation

The workable patterns all share one property: they stop treating the handoff as a summary and start treating it as an address. A task contract does not describe the world; it tells the receiver where the world can be found. The sender's context was always a cache. The environment is the source of truth.

Notice what this implies about when multi-agent systems are worth building at all. Parallelism pays when the tasks are genuinely independent. Specialization pays when the subagent's world is different in kind, not just smaller. The seams are where the work goes to die — so the design question, before any of the easy ones, is simply: where does the world live?

The future is not one agent that holds the world, nor many agents that summarize it to each other. It is a durable, structured, shared world that no agent holds and every agent can read. Build that, and the handoff becomes what it was always meant to be: a pointer.
