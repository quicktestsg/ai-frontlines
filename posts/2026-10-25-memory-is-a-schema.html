Memory Is a Schema, Not a Dump

Every agent framework now ships a memory feature, and almost all of them are the same product underneath: an append-only pile of embeddings with a similarity search bolted on top. It is a seductive pitch, and it fails in a characteristic way — the agent confidently recalls things that stopped being true, and nobody can debug it, because a vector dump has no schema to inspect.

The pattern is remarkably consistent across the ecosystem. A session ends; a summarizer compresses it into 'memories'; the memories are embedded and written to a vector store; next session, retrieval similarity-searches the pile and pastes the top-k chunks into the prompt. It works, briefly, on demos. Then real usage arrives. The same fact gets written forty times in forty phrasings, and retrieval returns the most emphatic phrasing rather than the most current one. A preference stated once and a preference retracted last week sit at identical coordinates in embedding space, and nothing knows which one is alive. The disease is not in the read path — it is that nobody ever decided what a memory is.

The two stores ingested identical traffic. The dump accumulated every phrasing of every statement, dead and alive — embedding distance cannot read a timestamp it was never given. The schema kept one row per keyed fact, writes a supersede chain when facts change, and carries a source link and a shelf life on every record. When the user flips a preference, the schema has an event; the dump has just acquired another neighbor.

Writes are the hard part

The industry's mental model of memory is read-heavy: the interesting question is always 'how do we get the right memories back?' But every durable system built before LLMs learned the opposite lesson — writes are where correctness lives. A memory write is not an append; it is a transaction against a world model. It needs normalization, conflict resolution, tombstones — because 'this fact is no longer true' is itself a fact — and provenance, because a memory without provenance cannot be audited, and a memory that cannot be audited will eventually be trusted by exactly nobody.

The stages most products skip are precisely the ones that make recall trustworthy later. Normalization decides whether the system has one fact in three costumes or three facts in one trench coat. Validation attaches the metadata the read path will depend on: type, source, and a shelf life. Resolution is where the world model actually updates: a contradiction must supersede, merge, or escalate — silently doing none of the three is how memory rots while looking healthy.

A store that remembers everything and forgets nothing knows nothing. Trustworthy memory is not recall of the past — it is a maintained model of the present, with receipts.

The read path inherits everything the write path earned. Once facts have keys, retrieval stops being a similarity lottery and becomes a query plan: resolve entities first, look up rows directly, fall back to semantic search only for the genuinely fuzzy residue — index seek before table scan, the same shape database engines converged on decades ago. Provenance turns every recalled fact into a citable claim, so a wrong memory becomes traceable to the message that planted it: the difference between a bug report and a mystery.

Retrieval designed as a query plan changes the failure profile of the whole system. Entity lookup gives deterministic answers for the facts the task most depends on. Semantic search is demoted to what it is good at: the long tail of vague relevance no schema anticipated. Assembly discounts stale rows and attaches sources, so everything that reaches the prompt is citable. When recall is wrong, there is a row, a key, a supersede chain, and an originating message to look at. Memory incidents stop being folklore and start being tickets.

There is a reasonable objection: schemas are rigid, and the promise of LLM agents is flexibility. But this misreads where flexibility belongs. The model is the flexible part; the memory is the part that must not be. A person can improvise a response to a surprise — what they cannot do is improvise their own past. The durable move is a two-tier design: a small, rigidly schematized core of keyed facts, identities, and commitments the system is willing to defend, and a large, loosely structured annex of episodic detail treated as advisory. Errors in the annex cost fluency; errors in the core cost trust.

The endpoint: memory stops being a feature and becomes an owned asset with a lifecycle — migrations, test fixtures, garbage collection with policy, and an interface other systems can join against. It is the standard biography of any storage system that survived production. The open question is how many 'the agent remembered it wrong' incidents each team needs before it stops shopping for better embeddings and starts hiring the discipline databases already learned. The pile remembers everything. The schema knows what happened. Only one of those is a product.
