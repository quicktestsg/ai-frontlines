The Watchdog Layer

Every autonomous agent has a blind spot the exact shape of itself. The loop that executes the task cannot also observe the loop — its attention is consumed by the work, and degradation never announces itself from inside.

Here is a pattern that recurs in every postmortem of a runaway agent. The system was given a goal. It worked, for a while. Then something shifted — a tool started returning errors, a retrieval step came back empty, the task turned out to be harder than the context allowed — and the agent's behavior quietly changed shape. It began repeating itself. It burned through its step budget, then the extended budget, then the emergency budget.

Left: the agent trying to observe itself — the observer sits inside the same context that is degrading, so the failure and the detection of the failure fail together. Right: a watchdog outside the loop, reading only the trace — it shares no state with the agent, so it cannot be corrupted by whatever corrupted the agent.

The observer cannot share a skull with the observed

The instinctive fix for runaway agents is to add monitoring instructions to the system prompt: 'if you find yourself repeating, stop and reconsider.' This feels reasonable and does almost nothing, for a structural reason that has nothing to do with model capability. The agent's attention is a finite resource, and it is already fully allocated to the task. Asking the model to watch itself while it works is asking one process to be both the worker and the inspector — and when the work gets hard, the inspection is the first thing abandoned.

A system that depends on the failing component to report its own failure has not one system but zero. The watchdog's defining property is not intelligence — it is separation. It must not share state, share context, or share incentives with the thing it watches. An observer that can be corrupted by the same event that corrupted the agent is not an observer. It is a passenger.

The triad: heartbeat, tripwire, kill switch

Watchdog engineering, as it has converged across mature agent deployments, rests on three primitives. The heartbeat is the agent's proof of life: a periodic signal emitted between steps. The tripwire is a pre-declared invariant placed on the trace, checked outside the agent. The kill switch is the watchdog's authority to stop the run — pause, snapshot state, escalate. The order matters: heartbeat detects silence, tripwires detect noise, the kill switch converts detection into consequence.

The heartbeat flows out of the loop between steps. The trace log streams alongside it. Tripwires — declared before the run, evaluated by ordinary code — sit on the trace, not in the prompt. When one snaps, the watchdog exercises the kill switch: pause, snapshot, escalate. Every arrow of accountability routes around the agent, never through it.

Tripwires are declared, not improvised

There is a temptation, once the watchdog exists, to make it clever — to give it a model, have it read the trace, and decide whether the agent 'seems to be doing well.' Resist this. A watchdog that reasons probabilistically about the run inherits every property that made the agent unsafe in the first place. The tripwires that earn their keep are embarrassingly simple, and they work because they are declared before the run and evaluated by unglamorous code.

A trace that degrades: the first steps advance, then the run starts circling — the same tool, the same arguments, the same result, feeding the same decision. The agent registers none of it, because from inside each step looks locally reasonable. The tripwires snap on schedule, indifferent to how reasonable each step looked.

Fail static, not silent

The last property of a real watchdog is the most counterintuitive: when the watchdog itself fails, the system should stop, not continue unobserved. A watchdog that crashes quietly and leaves the agent running unsupervised has converted a small failure into the exact catastrophic mode it existed to prevent. The watchdog is in the critical path by design.

None of this is a statement about models being untrustworthy. It is a statement about topology: any process sufficiently complex to be useful is insufficiently positioned to observe itself, and the more capable the process, the more expensive its quiet failure modes become. Build the agent to be clever. Build the watchdog to be bored, suspicious, and always on. The pairing is not redundant. It is the first honest architecture autonomy has ever had.
