The Checkpoint Contract

Every sufficiently long agent run will be interrupted. A deploy ships mid-task. A rate limit trips. The context fills. A human closes the laptop.

There is a quiet assumption buried in most agent architectures: that the process which starts a task will be the process that finishes it. It is a reasonable assumption for a chatbot answering in fifteen seconds. It is fiction for anything interesting.

A long run is not a straight line but a line peppered with stops. Deploys, rate limits, context ceilings, and absent humans are not bugs; they are Tuesdays.

Replay is not resume

The naive answer to interruption is replay: run the whole task again from the top. It feels safe because it requires no new machinery. It is actually the most dangerous option on the table.

Resume is a different operation entirely. To resume is to restore a saved state and continue from it — which means someone had to decide what 'the state of an agent run' is.

A crash at step seven. Above: the run restarts from zero, re-paying for every step. Below: the run restores the checkpoint and continues. Same crash, different bill.

The three clauses

A useful checkpoint answers three questions, and only these three. What happened. What was committed. What remains. Anything else is padding. Anything missing is a landmine.

The checkpoint contract: a distilled trace, a ledger of committed actions, and a live plan. Skip a clause and the resume still 'works' — until the exact situation the clause existed for arrives.

Game engines have saved state since the 1980s; databases have had write-ahead logs for longer. The pattern arrives late to agents because the industry's mental model of an agent is still a conversation — and conversations are assumed ephemeral.

An agent that cannot be interrupted can only be abandoned. The systems worth building are the ones a human can walk away from at 6pm and a machine can pick up at 3am — with no duplicated emails to show for the handoff.

A forty-minute run is not a long request; it is a small project, and projects have always needed progress records, commit points, and a definition of 'where we left off.'
