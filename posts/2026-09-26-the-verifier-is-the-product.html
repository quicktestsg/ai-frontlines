The Verifier Is the Product

Generation has become a commodity. What has not is knowing whether the generated thing is correct. The scarce engineering asset inside an agent system is the verifier — and in any domain where correctness matters, the ceiling of the system is not what the model can produce. It is what the system can check.

Watch how agent systems are demoed and a pattern emerges within minutes. The demonstration is always an ascent: look what the model wrote, look what it built. What is never shown is the answer to the only question a production customer asks: how do you know that is right? The uncomfortable truth underneath most agent failures is not that the model was too weak. It is that nothing in the system was ever in a position to notice the output was wrong.

This reframes what an agent product actually is. The model is a supplier. The prompt is a supplier. Retrieval, tools, memory — suppliers, all interchangeable and re-priced every quarter. The product is the pipeline that turns unreliable generation into reliable delivery, and the core of that pipeline is a verifier with authority: the right to reject, repair, escalate — and, most importantly, the right to say 'this cannot be checked, therefore it cannot be promised.'

Suppliers feed the verifier; the verifier owns the outcomes. Swap the model and the verifier re-prices it automatically. A system organized the other way inherits every supplier's failures and has no way to notice.

The verifier hierarchy

Not all verification is equal, and the discipline is knowing which tier a given check lives on. At the base: exact verification — compile it, run it, diff it. Binary, cheap, utterly trustworthy. Above it, structural verification: schemas, types, constraints. Above that, semantic verification — a model judging a model, probabilistic, itself in need of evaluation. At the top, humans: the most expensive check, which means every lower tier's job is to ensure humans only see what only a human can judge.

Trust is highest at the bottom and cheapest there too — a rare free lunch in systems engineering. The hierarchy is an order of exhaustion: exact checks before structural, structural before semantic, semantic before human. A system that skips to the top is not being careful. It is being careless at maximum cost.

The verifier inside the loop

There is a subtler failure mode than a missing verifier: a verifier that is technically present but structurally powerless — running after the loop exits, on a dashboard nobody watches. The verifier earns its keep inside the loop, where its judgment has consequences. This is what separates a repair loop from a retry loop: retries resample and hope; repairs feed the exact defect back, so each iteration carries information the previous one lacked. Retries flatten; repairs compound.

Both loops contain a verifier, but only the right one connects the diagnosis back to the generator. The retry loop is a coin flipped harder; the repair loop is a conversation. Without carried diagnosis, additional attempts buy almost nothing — with it, success compounds until the remaining failures are genuinely hard, at which point escalation to a human is correct, not defeat.

Build the verifier first

The practical consequence inverts the usual build order. Before writing the first prompt, write the golden set — inputs with known-correct outputs, drawn from the real distribution, including the ugly cases. Then build the harness that scores any candidate against it. Only then plug in a generator. Model swaps become A/B tests, prompt changes become diffs, and 'the new model feels better' becomes a sentence not allowed in design review.

A generator answers 'what could this be?' A verifier answers 'is this actually right?' Only one of those questions can be asked before something ships. The obsession with the first and the amnesia about the second explains most of the gap between agent demos and agent products.

None of this argues against better models — better generators raise the base rate of everything. The argument is about where the durable engineering lives. The generator's quality is rented: it resets with every release, for every competitor, simultaneously. The verifier's quality is owned: golden sets, repair loops, hierarchy discipline, escalation paths — these compound, and no competitor can download them. Six months from now the model will have been swapped twice. The verifier will still be there, quietly deciding what ships. That is the product.
