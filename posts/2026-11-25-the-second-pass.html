The Second Pass: When the Loop Moves Inside the Model

For ten years, a model's depth was frozen at training time. Every layer ran exactly once per token. Recurrence is back — not the RNN of the 2010s: looped blocks keep the weights, re-run the middle of the network, gate what the first pass commits, and hold the working set in a tiny KV window. Depth is becoming a runtime budget.

Depth has always been the bluntest instrument in the stack. Want a smarter model? Add layers. Each one runs once per token, forever, for every token — the trivial punctuation and the decisive branch point get the same compute. The uniformity was never a design choice; it was an inheritance. Feed-forward networks are amortization machines: pay for the weights once, then run them at a fixed rate.

The looped block breaks the flat rate. The recipe is almost embarrassingly simple: take a pretrained model, freeze what it knows, and train the middle layers to run again — two, three, four passes over the same token before the representation is released. Between passes, a per-token gate decides how much the first pass writes into the residual stream; the loop reads through a small KV window. In ablations, roughly ten percent more compute lifted a competition-math score from 19.2 to 30.4. The same weights, asked twice, are smarter than asked once.

Left: the inherited contract — every layer runs once, for every token, at the same flat rate. Right: the looped block — the middle of the network re-runs under a budget, a per-token gate controls what the first pass commits, and the loop reads through a working set small enough to stay cheap. Same weights. Different pricing.

Weights are a sunk cost; passes are a spot market

The right way to read a looped model is as two compute markets. The weights are the amortized market: paid once, at training, reused forever. The passes are the spot market: paid per token, at the moment of need. Bigger weights buy capability that is cheap to serve but expensive to acquire — uniformly, for every token. A second pass buys capability that is expensive to serve and free to acquire — selectively, only where the token is hard. The economics point in opposite directions, which is precisely why the combination is interesting.

This reframes the scaling debate. The old question was how big; the new question is how much, when, and for which token. A routing layer that pushes filler tokens through one pass and reasoning tokens through four is doing per-token compute allocation — load balancing for depth. Pass counts become a knob on the request, mixed in with batching and cache policy. The model stops being a fixed point on a capability curve and becomes a dial.

A loop in the harness burns context. A loop in the weights burns compute. Both burn money. The engineering question is identical at both levels: how much, and who decides when to stop.

The gate is the architecture

The naive version of looping — just run the middle again — does not work, and the reason is instructive. On the second pass, the block is looking at its own output. If the first pass wrote everything, the second echoes, and the echo compounds until the representation saturates. If it wrote nothing, the loop is a rerun with noise. The gate is what makes the second pass possible: a per-token decision about how much of the first draft survives into the second reading. Open it fully and the block repeats itself; close it fully and the block contradicts itself. The productive setting is in between.

It is worth pausing on how strange this is, architecturally. The gate is a merge policy between two drafts of the same thought, executed inside the forward pass, learned rather than written. Engineers who have built reconciliation logic — transactions, concurrent edits, agent sub-results — will recognize the shape: two versions of the truth, a policy for which parts win, failure modes at both extremes. The old rules still rhyme: an over-committed first pass is a lock taken too early; an under-committed one is a transaction that never engages.

Quality per pass rises fast and then flattens — the knee. Cost rises linearly and never stops. The engineering is in the middle zone: enough passes to clear the knee on the tokens that matter, one pass on everything else. That judgment is a routing decision, and it is now part of inference infrastructure.

More passes, fewer fires

The most under-discussed result in this line of work is behavioral, not benchmark-shaped. In research variants, repeated passes over the same token were associated with a sharp drop in destructive actions — single-pass models acted harmfully at a substantial rate; four passes collapsed that rate by roughly an order of magnitude. The mechanism is not mysterious: a model that re-reads its own intermediate state gets more chances to notice what it is about to do. Deliberation, at the layer level, behaves like suppression. The model catches itself.

But the same observation cuts the other way. Pass count is now a behavior-relevant parameter that can be changed without touching a single weight — the same model, served at one pass and at four, is observably a different agent. Every safety property validated at one setting must be re-validated at the others, because the loop amplifies whatever the middle block does, not just the intended parts. The pass count belongs in the evaluation matrix, next to temperature and system prompt.

Agent loops and layer loops obey the same three laws — a budget, a bounded working set, an explicit stop — and fail the same way when a law is missing. Teams that learned this discipline on harnesses will recognize it immediately in the forward pass.

There is a larger pattern here worth naming. Loop engineering spent two years being a harness discipline — steps, tools, retries, guards, budgets — all written around a model that was, internally, a straight line. That era is ending. The model itself is becoming a loop, and the same vocabulary — budget, gate, working set, exit — reappears one level down, attached to learned components instead of written ones. The engineers who treated loop design as a craft have already done the intellectual work. They were just aiming at the wrong layer.

The destination is compute-elastic intelligence: models whose effective depth is a request-time decision, whose cost tracks the difficulty of the token, and whose behavior changes when the dial moves — measurably, sometimes for the better, always in ways that must be evaluated. Depth used to be a training decision. Now it is a serving decision. The loop has finally moved inside, and it brought all the old rules with it.
