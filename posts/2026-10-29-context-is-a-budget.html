Context Is a Budget, Not a Bucket

The context window looks like memory, but it is nothing like memory. Memory stores a byte once and lets you read it for free. Context rehearses every resident token on every generation step — and the rent compounds. The agents that fail at hour forty rarely ran out of intelligence. They ran out of solvent context.

There is a category error at the bottom of most agent failures, and it is almost never named. Engineers are trained to think of capacity as storage. A disk fills up; you delete something; life continues. This reasoning is silent about the one thing that matters: in a transformer, residence is not free. A token in context is not stored. It is rehearsed. On every single forward pass, that token is attended to by every other token, and every other token is attended to by it. The bill arrives at generation time, every time, for the entire contents.

Two currencies are being spent, and teams usually only track one. The first is compute: attention cost grows with the square of sequence length. The second currency is subtler and more expensive: attention itself. Every irrelevant resident token competes for attention against the tokens that matter. The bucket mental model says the failure threshold is the window limit. The budget mental model says the threshold arrives far earlier — at the point where the signal the task needs can no longer win the attention auction against everything else resident. Most long-running agents go bankrupt that way: not full, but insolvent.

A typical long-run ledger. Fixed residents pay rent on every forward pass whether or not they are used. Discretionary residents accumulate over the run and never leave. What remains for the actual work of the task is the residue. The window was never the constraint. The ledger was.

Fixed costs crowd out the work

The first discipline is to notice how much of the ledger is fixed, and how little scrutiny those fixed costs receive. The system prompt is the most-read document in the entire system and the least-tested artifact. Tool schemas are worse, because they multiply. A harness with forty tools where the median task uses three is carrying a permanent tax of thirty-seven irrelevant passengers. The fix is not fewer capabilities — it is tiered residency. Tools become pages brought in on fault, not resident libraries.

A token in context is not stored, it is rehearsed. Storage is paid once; rehearsal is paid per performance, and the model performs at every step. Budget accordingly: anything that rides along for a thousand steps must justify itself a thousand times, not once.

Eviction is a policy, not an accident

The discretionary side of the ledger — documents, results, history — is where runs die. The default eviction policy in most agent frameworks is, astonishingly, none. Oldest-first is the worst sensible policy, because in an agent run the oldest tokens are often the most load-bearing. Clipping history from the front is evicting the lease while keeping the furniture. A serious harness treats eviction as an explicit policy with named tiers: pinned, summarized, and volatile.

One long run under three policies. Never-evicting grows until the run hits the ceiling and dies. Oldest-first clipping keeps the load flat but amputates the task statement and the plan — the agent keeps working, on the wrong problem. Tiered eviction produces the compaction sawtooth: load rises, summary collapses it, pinned invariants survive every collapse. Only the third shape reaches hour forty still knowing what it is for.

Compaction is amortization — carry invariants, not narrative

When history is summarized, something is always lost, so the design question is not whether to lose information but which information. Bad compaction compresses narrative. Good compaction compresses like a closing accountant: the ledger is closed, the balances are carried forward. The run can afford to forget how it knows, as long as it never forgets what it knows. Teams should audit compaction the way finance audits closing entries: after each summary, check that every invariant survived the collapse.

Compaction as closing the books. Raw history flows in; a filter separates settled facts from narrative; a small carried ledger flows out and the run continues on it. What is amortized to zero is the story of the work — how each fact was learned — never the facts themselves. A well-audited compaction is why an hour-forty agent still behaves like minute-one.

Run the budget like a budget

None of this requires a new framework. It requires a posture change: context allocation is an engineering artifact with owners, reviews, and metrics. Practically, three habits: instrument the ledger; review fixed costs on a schedule; test compaction for invariant survival. The window will keep getting bigger. It does not matter. Budgets are not about the size of the account; they are about the decision of what deserves to live in it. The teams that internalize this build agents that run for days on any window. The teams that do not build agents that fit in any window, briefly.
