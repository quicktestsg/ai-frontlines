The Handoff Is the Contract

Multi-agent systems rarely fail at the agents. They fail at the seams — the precise moment one agent hands work to another. The teams that build systems which actually compose treat the handoff as a contract.

Every multi-agent system is a set of agents plus the gaps between them. The agents get all the attention — but watch a real system run and you will see that almost nothing interesting happens inside a single agent. What determines whether the whole thing works is what happens in the gaps.

A handoff looks trivial. The naive implementation passes everything: the entire conversation history, all tool outputs, every intermediate thought. This is not a handoff; it is a context dump. The receiving agent drowns, and worse — it inherits the sender's confusions, laundered into apparent authority.

A real handoff is a packet with five fields: the goal, compressed to one sentence; a context slice containing only what the receiving agent needs; the tool scope it is allowed to touch; the schema its answer must satisfy; and a budget. Everything else stays behind. The packet is the contract — it can be logged, tested, versioned, and replayed, which no context dump can ever be.

Why fresh context beats inherited context

The instinct to pass everything comes from a reasonable place: context seems free, and more information seems strictly better. Both halves of that intuition are wrong. Context is not free — every inherited token competes for attention, dilutes the task, and costs money on every subsequent call.

A handoff is a compression act. The sender's job at the moment of handoff is to compress: to take everything it knows and produce the smallest packet that makes the receiving agent effective. This compression is not overhead. It is the intellectual work.

A handoff is a boundary, and a boundary is a feature. The seam is where noise dies. Teams that blur the seam import the noise. Teams that honor the seam get focus for free — and focus, not intelligence, is the scarce resource in every multi-agent run.

The return schema is the half everyone forgets

Teams that get the outbound half right often still fail on the return. The worker finishes its task and sends back... something. A paragraph of prose. The orchestrator must now parse it — a probabilistic act, which means another place where the system can misread or hallucinate structure that is not there.

The fix is the return schema: the contract's clause about the shape of the answer. A schema forces the worker to decide what it actually found, lets the orchestrator trust the result mechanically, and makes the handoff testable. Prose is for humans. Contracts are for agents.

Two wires, same work. On the prose wire, trust is guessed, one parse at a time. On the schema wire, validation is code: the packet either conforms or it doesn't, and a non-conforming result is returned to the worker, not absorbed into the plan.

Three anti-patterns, named

Once you start looking at handoffs as contracts, the failure modes become easy to name. The whisper, the fire-and-forget, the boomerang. Each anti-pattern is a broken clause in the contract. Each has the same repair: write the clause.

The whisper never creates a boundary, so nothing is compressed and noise rides along. The fire-and-forget delegates without a return schema, so results come back unverifiable. The boomerang returns process instead of answers. Every anti-pattern is a missing clause.

There is a test for whether a team has real contracts or just vibes: take a completed multi-agent run and delete the agents. If the handoff packets and return schemas still exist — logged, inspectable, replayable — the team has contracts. The agents are ephemeral. The contracts are the durable artifact. Multi-agent systems don't run on intelligence. They run on the seams.
