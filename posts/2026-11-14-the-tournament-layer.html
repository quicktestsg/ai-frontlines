The Tournament Layer

Every generation of models narrows the gap between a mediocre prompt and a brilliant one, and what remains controllable shifts one level up. The most powerful inference knob left is not the prompt — it is the number of attempts bought.

There is an uncomfortable measurement buried in most agent evaluation harnesses: run the same task twice with the same model and the same tools, and the success rate moves not by decimals but by tens of points. Trajectory quality is dominated by early decisions — which file gets read first, which hypothesis gets entertained, which tool gets tried — and each of these is sampled, not decided.

Left: the default architecture — the entire budget spent on a single sampled trajectory, where an unlucky first decision compounds silently into the final result. Right: the tournament layer — the same budget split across divergent branches, each free to be wrong, with a scorer choosing what survives.

Correlated failure is the silent killer

A tournament multiplies nothing if the branches agree. Two trajectories that read the same files in the same order, form the same hypothesis, and fail against the same wall are not two samples — they are one sample, paid for twice.

Width without diversity is theater. Five identical attempts dressed as five options produce the confidence of exploration and the results of a coin flip.

Diversity is a property of inputs, not of hopes. The strong levers — retrieval sharding, task decomposition, tool ordering, model choice — change what each branch knows before it starts thinking, which is the only thing that reliably changes how it fails.

The scorer is the product

A tournament never produces the best answer. It produces the answer that looks best to the scorer. In verifiable domains the scorer can be ordinary deterministic code, and the tournament is close to free quality. In preference domains the scorer is a model, and the tournament inherits every weakness of that model.

The same compute can be spent two ways: width, split across raced branches with selection; or depth, poured into one long trajectory. Width rises fast but plateaus; depth starts slow and keeps climbing. Neither dominates — the crossover moves with the cost and reliability of the score.

Where tournaments must not run

The tournament layer has a hard boundary: side effects. Racing five trajectories is only safe while the world sees one. The moment a branch sends the email, charges the card, or merges the pull request, the other four branches stop being discarded samples and start being uncommitted consequences.

None of this argues for tournaments everywhere, and the economics decide most cases without sentiment. Racing multiplies the cost floor by N and buys a distributional edge whose size is set by variance, diversity, and judge quality. The mature position is a per-task decision, made on measured variance and scorer reliability, with the membrane around the arena and a single commit on the way out.
