Every Tool Call Is a Transaction

A talking model that fails loses a sentence. An acting agent that fails leaves the world changed anyway. The tool timed out — but did the invoice get sent? The loop cannot know, and its reflex, retry, is precisely the wrong move for anything that mutates state.

There is a genre of agent failure that never appears in demos. The agent is filing the quarterly invoices. It calls the billing tool, the request sails off, and then the network hiccups — no response, no error, nothing. The harness does what harnesses do: it retries. The second call succeeds, a green checkmark lands in the transcript, the agent reports completion. Somewhere downstream, a customer has been charged twice.

The canonical acting-agent failure. Call one times out, but the timeout carries no information about whether the effect landed. The harness retries — the correct move for a read, a destructive one for a write. The transcript shows a clean run. The world shows a duplicate.

Timeouts are lies

The root confusion is about what a timeout means. To the harness, a timeout looks like failure. But a timeout is not a report from the remote system — it is a local decision, made by a clock, that waiting any longer is too expensive. The truth is always one of three states, never two. A timeout collapses all three into one bit, and the retry policy then bets the customer's money on a guess.

A read can be retried blindly because the world owes it nothing. A write cannot, because the world keeps score. Any harness that treats them identically has not designed its actions — it has merely scheduled them.

The side-effect spectrum

The fix starts with admitting that tools are not interchangeable. Line them up on a spectrum of blast radius. The single most useful artifact an agent team can produce is this classification for their own toolset — because every property of the call should follow from its position.

Tools ranked by blast radius. Pure reads are free. Reversible writes need an idempotency key and a designed undo. Hard writes need reconciliation before any retry. Irreversible actions need human sign-off, caps, and the two-person rule. The position on this bar should decide everything else.

Keys and ledgers

For everything right of pure reads, two mechanisms do most of the work. The first is the idempotency key: the harness mints a unique key for the intended effect and passes it along. The remote system records the key when it acts; if the same key arrives twice, it returns the original result instead of acting again. The key must be minted by the harness at plan time — a model under context pressure will happily invent a fresh key for a retry and defeat the entire mechanism.

The second is the transaction ledger. Every write, keyed, timestamped, with its arguments and its status — appended to a durable log before the call is made. The ledger converts recovery from guesswork into replay. Reconciliation — querying the actual remote state against the ledger — is the only honest answer to the three-states problem.

A crashed agent wakes with empty context and one honest asset: the ledger. Reconciliation resolves each ambiguous entry by querying the world — three outcomes only: landed, resume; never landed, retry with the same key; unknown, stop and escalate.

The harness is the accounting department

None of this is a limitation on agent capability; it is the precondition for it. The teams that ship acting agents people actually trust will not be the ones with the smartest models. Intelligence chooses the action. The harness guarantees that it happens exactly once — or not at all, loudly.
