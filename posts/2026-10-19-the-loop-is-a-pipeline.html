The Loop Is a Pipeline, Not a Turnstile

Every discussion of agent costs eventually lands on tokens. Almost none of them lands on seconds — which is strange, because users experience the agent in seconds, and seconds are made mostly of waiting.

Take an ordinary trace and color it by who is working. The picture is embarrassing. During model inference, every tool is idle. During tool execution, the model's weights sit cold in someone else's datacenter doing nothing for this run.

The same four stages, scheduled two ways. On the left, the sequential loop: each stage completes, hands off, and waits — total time is the sum of all stages plus every gap. Below it, the pipelined loop: while the tool executes step n, the model is already reasoning about step n+1 and a prefetcher warms step n+2.

Speculate on the next tool call

The most valuable overlap is also the most radical: start the next step before the current one confirms it. Agent behavior is far more predictable than it looks. A run that just read a file very likely reads a related file next; a run that found one search hit very likely fetches the same domain again.

Speculation has a bad reputation in this context, earned by people who speculated with writes. The rule that keeps it honest is old and simple: speculate on reads, serialize writes. A read has no side effects — warming it costs electricity, not correctness.

Speculative execution, safely. While step n's tool runs, a cheap predictor warms the most likely reads for step n+1. Hits start warm; misses are dropped without a trace — reads have no side effects. Writes never speculate.

Overlap starts in the harness, not the model

None of this requires the model provider to change anything, which is the point. The harness owns the loop, and the loop is where the scheduling lives. Cheap first moves: batch independent tool calls instead of dribbling them one per turn.

Cost gets optimized where it is measured in tokens. Latency gets optimized where it is measured in gaps. The teams that feel fast are not the teams with the fastest model — they are the teams that refused to leave their pipeline idle.

The accounting changes when the clock overlaps

There is a second-order effect that deserves attention. Once reads are speculative, the marginal cost of an extra read collapses — a wrong guess costs milliseconds of prefetch, not a visible step in the user's trace.

The marginal cost of gathering context, sequential versus speculative. Sequentially, every additional read is a full visible step — latency and token budget both — so the agent rations what it looks at and guesses the rest.

The uncomfortable summary: most agent latency is not model latency, and most of what is billed as 'thinking time' is actually scheduling debt — gaps the runtime left open because nobody owned them.
