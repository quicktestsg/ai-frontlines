The Name Is the Foreign Key

An agent is a fuzzy matcher running inside a system that needs exact keys. Nothing crashes when identity fails — the work silently forks.

Consider a failure that never appears in any incident review, because nothing technically failed. Three sources, three phrasings, one underlying object — and the join failed, because nothing in the system ever states, in a form code can check, that these mentions point at one thing.

This is the identity gap, and it widens exactly as agent systems get more capable. Databases solved it half a century ago: every row gets a key, and every reference uses the key, never the description.

Top: one object, five names. Middle: without a join key, working memory forks it into disconnected shadows — nothing errors, everything degrades. Bottom: the fix is the oldest idea in databases.

Paraphrase is a UI feature, not a data model

The root confusion is treating the model's fluency as a storage layer. Fuzziness at the edges of a system is a gift; fuzziness in the middle of it is a rounding error on reality, compounding hourly.

A name that must be re-guessed on every use is not a name. It is a riddle the system pays to solve again and again — sometimes incorrectly, always silently.

Mint identities at the edge, reference them in the core

The pattern is a split: the fuzzy matcher resolves names to IDs at the edge; exact keys drive every action in the core. The model may still write 'the login bug' — but the structured envelope says entity:e-1041.

The identity perimeter: resolve every mention to a canonical ID at the boundary. Inside the core, everything keys on the ID. Prose may paraphrase; envelopes never do.

Identity is half the problem — the other half is staleness

Entities need two fields: identity and version. The ID says which object is being touched; the version says whether what the agent believes about it is still true. Optimistic concurrency control, lifted from databases into agent loops.

Every consequential action starts with a compare: context version against world version. Match — act. Mismatch — re-fetch, re-validate, act.

The counterargument — that long-context models will dissolve the identity problem — fails because the problem is not in the model, it is in the world. Context windows do not freeze a ticket's state while the agent thinks. Coordination problems live in the architecture, not the weights.
