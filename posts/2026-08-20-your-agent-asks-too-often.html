Your Agent Asks Too Often

An agent that asks before every action is not safe — it is a subscription to interruption. Every approval request spends the scarcest resource in the system, and attention is a budget that depletes, not a service that scales.

There is a number every deployed agent has, and almost no team can state it: how many times, per completed task, the agent stopped and asked a human for permission. Not the accuracy. Not the latency. The interruption count. It is the number that decides whether the product feels like delegation or like babysitting — whether the user walks away and the work continues, or the user stays tethered to a queue of yes/no questions that arrives faster than it can be read.

Human attention does not scale. This is the constraint that every autonomy feature runs into, eventually, at full speed. Models get faster, tools get richer, and the queue of decisions an agent must make grows by the week — but the human on the other end still reads at the same speed, still context-switches at the same cost, still has the same half-hour of genuine scrutiny in them per day. Every approval request draws from that fixed pool. Most teams treat asking as free, because the cost lands on someone else's calendar. It is not free.

Every decision an agent faces has a home. Reversible actions inside the sandbox execute and log. Actions covered by a pre-approved policy execute if they match, and escalate if they do not. Only the third pipe — the irreversible and the uncovered — is allowed to interrupt a human.

The rubber stamp is a latency injector

What attention does under repetition is well documented, and it is not flattering. The first approval of a session gets read. The third gets skimmed. The tenth gets approved with eyes already back in the code review tab. By the twentieth, the prompt has become a reflex: locate the button, click yes, return to work.

Actual scrutiny collapses within the first handful of interruptions, while the blast radius of the average request keeps growing as the session deepens. Past the crossover, the least-read approvals carry the largest consequences.

This is why the interruption count cannot be tuned down with a smarter model or a better-worded prompt. If 98% of everything routed to the human gets approved, the approval step is not a control — it is theater with a queue. In production, a mostly-yes approval flow trains the human to be a rubber stamp, converts the safety feature into a latency feature, and quietly moves the actual safety boundary to wherever it was always going to land.

An approval prompt is not a safety feature. It is a transaction: risk reduction purchased with the scarcest currency in the system. Spend that currency on instances and it evaporates within a week. Spend it on policy and it compounds.

Approve the class, not the instance

The fix is to change the unit of approval. Most systems approve instances: may the agent run this command, send this email, spend this amount — now, stripped of the context in which the plan was made. The instance is the wrong unit. It arrives without history, without proportions, and without any way for a human to do better than a two-second guess. The better unit is the policy: a pre-made answer to an entire class of decisions.

On the left, instance approval: every action pings the human, each ask arrives stripped of context, and attention evaporates into reflex. On the right, policy approval: one deliberate decision licenses a thousand actions inside a sandbox with walls and an audit log, and only the genuinely uncovered case surfaces.

The axis that decides which bucket a decision belongs to is not how sensitive it sounds, but how expensive it is to undo. An action that costs a keystroke to reverse should almost never interrupt a human. An action that cannot be reversed at all should almost always be explicit. Between those poles, the system's job is to move actions downward — to make the irreversible cheaply reversible — through tool design rather than heroic restraint.

Make silence mean the safe branch

And on the rare occasions the ask is genuinely owed, it must be built like a product surface, because it is one. A good escalation carries four things: what changed since the approved plan; what specifically is at risk if this proceeds; what happens on each answer; and the default if no answer arrives. Most prompts in the wild carry none of these.

The default is the part that decides everything, because eventually it is the only part that runs. Users go to lunch, change jobs, leave the company; on-call rotations acknowledge from their pockets at two in the morning. Whatever the system does when no answer arrives is, summed over the lifetime of the product, its real policy on human oversight. There is exactly one defensible choice: silence maps to the safe branch — hold, revert, downgrade, discard. Never to the ambitious one.

The measure of an agent is not how smart it is. It is how rarely it needs to interrupt a human, and how much it nevertheless accomplishes. Autonomy is not granted at launch; it is earned in layers — read-only first, then writes inside a sandbox, then bounded spending, each expansion justified by clean traces and an audit log that survives scrutiny. An agent that asks about everything trusts nothing — including its own architecture. An agent that almost never asks has something better than trust: bounds.
