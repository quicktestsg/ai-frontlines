Traces Are Core Dumps

An agent fails at 3 a.m. and the error message says a tool returned 500. That explains nothing. Agents fail in ways only a complete recording can explain — and the trace is not a log, it is a core dump.

Systems people of a certain age remember core dumps: when a program crashed, the OS wrote the entire contents of memory to disk, and the engineer who showed up next morning was handed the exact machine state at the moment of death. Agent systems need the same artifact and almost never build one.

A real trace records the experiment, not a summary of it: the exact prompt as rendered, every retrieved document, the full tool call arguments, and the raw tool response before any wrapper mangled it. The spans are secondary; the payloads are the artifact.

Replay, not re-run

The instinctive objection is that models are nondeterministic, so replay is impossible. This misreads what replay needs to be. Nobody re-runs the model during a post-mortem. Replay means re-reading: feeding the recorded sequence of observations back through inspection tooling, stopping time at any span, and asking 'given exactly this, what would a reasonable policy have done?'

A log answers 'what went wrong?'. A trace answers 'what would you have done, standing exactly where the agent stood, seeing exactly what it saw?' Only one of those questions finds root causes.

This distinction has a second-order consequence: it changes what harnesses are made of. A harness that intends to be replayed keeps tool results immutable and versioned; one that intends to be skimmed lets wrappers truncate and reformat in flight. Entire categories of bugs are only visible to the first kind.

Fidelity is a pyramid, not a switch

Recording everything forever is the strawman, and it fails the way hoarding always fails: the cost is linear and the value is not. Serious observability tiers fidelity by age and severity, the way flight recorders pair a loop tape with an incident dump that survives.

Full fidelity for hours, sampled structure for days, statistics forever. The interesting half is the freeze rule: any signal that a run mattered must promote its full payloads out of the garbage schedule immediately.

Diff two runs, not one

The most underused primitive in agent debugging is the trace diff. A single trace tells you what happened; two traces of the same task tell you where the worlds diverged — and the divergence point is usually the bug.

Given a golden trace and a failed trace of the same task, debugging becomes mechanical: replay both in lockstep, stop at the first divergent observation, and treat it as the root cause. Everything after is faithful compounding on a poisoned input.

The uncomfortable conclusion is that observability is not instrumentation bolted onto a finished harness — it is a load-bearing property of the harness itself. A team that ships first and plans to add tracing later has guaranteed that its first serious failure will be debugged blind, from testimony instead of evidence. Flight recorders are not installed after the crash.
