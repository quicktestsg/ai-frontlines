The Tool Call Is a Promise

Every agent run has one discontinuous moment: the tool call, where free tokens become real-world effects. The gap between what the schema says and what the world does is where agent systems bleed.

There is a moment in every agent run when the stakes change discontinuously. Until that moment, everything the system has done is generate tokens — plans, reasoning, summaries, JSON that might have been arguments — and all of it is free. The moment is the tool call: the only place in the entire architecture where the model's words become the world's deeds.

The tool call is the only door between the model's world, where generation is free, and the world's world, where nothing is. On the left, a wrong token costs nothing. On the right, every effect lands on someone.

Every tool is a promise

Look at what a tool definition actually contains. A name, a description written in hopeful prose, and a schema describing the shape of the arguments. That is the entire contract. The description says 'sends the quarterly report to the mailing list' — but says nothing about what happens when the list has three thousand members, or when the send succeeds halfway, or when the agent calls it twice because the first call was slow and it got nervous.

A prompt is advice. A tool schema is a contract. The agent's real safety policy is written in neither — it is written in what the harness does between the model's yes and the world's okay.

The model cannot keep the promise

It is tempting to file every bad tool call under model failure, but the categories are different. The failure this piece is about is the schema-valid, correctly-chosen call that still goes wrong, because the promise itself had holes. The timeout that fires after the effect. The retry that fires after the timeout. The tool that does two things but only documents one.

One schema-valid call, four possible futures: fast success, partial failure that commits rows then times out, slow success that triggers retries underneath, and the unnamed side effect. The schema guaranteed none of them.

The harness holds the promise

If the promise cannot be kept from the model's side, it must be kept from the middle — in the harness, at the last layer before execution. Validate the shape. Gate the irreversible. Scope the blast radius. Record everything. None of this constrains a well-behaved agent in the slightest; all of it converts the agent's worst days from incidents into log entries.

The kept promise: the model proposes, and before anything executes, the harness runs the gates — shape, consent, scope — and stamps every call with an idempotency key into a replayable ledger. The model proposes; the harness disposes; the ledger remembers.

The smallest possible tool

The design pressure that falls out of all this runs against instinct. When an agent needs more capability, the instinct is to hand it a bigger tool: more parameters, more modes, one endpoint that can do everything. Every added parameter is a new axis along which a slightly-confused model can be technically correct and practically wrong. The discipline is the opposite: the smallest tool that keeps the promise tight.

None of this is glamorous, and that is the point. Production agent systems live or die at an interface nobody demos: the moment a token stream becomes a side effect. Treat that moment with the respect a database treats a transaction. The model reads the marketing. The harness reads the promise. And the world, which has never once cared what the schema said, reads only what actually executes.
